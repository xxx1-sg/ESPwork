# 后端长期常驻说明

> 目标：开发板 7x24 上报，后端要一直活着 —— **关掉终端不会停、开机自动起、崩了自动重拉**。

## 一、已经装好了什么

| 组件 | 位置 | 作用 |
|---|---|---|
| 开机自启入口 | `启动文件夹\ESP_SensorBackend_Autostart.cmd` | 登录 Windows 时自动拉起守护（**已安装**） |
| 自启脚本（源） | `tools\ESP_SensorBackend_Autostart.cmd` | 上面那个文件的副本，改这里后重新复制过去 |
| 守护进程 | `tools\run_backend_forever.py` | 拉起后端；**崩了自动重拉**；日志轮转；防重复启动 |
| 停止脚本 | `tools\stop_backend.py` | 一键停掉守护 + 后端 |
| 后端访问日志 | `evidence\backend_run.log` | 每条上报/查询（超过 20MB 自动切 `.1`） |
| 守护自身日志 | `evidence\backend_guard.log` | 守护的启停、重拉记录（排查"到底有没有在守护"看这个） |
| 守护 PID | `evidence\backend.pid` | 后端进程号 |
| 单实例锁 | `evidence\backend_guard.lock` | 防止同时跑两个守护 |

启动文件夹的完整路径：

```
C:\Users\user\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\ESP_SensorBackend_Autostart.cmd
```

（在文件资源管理器地址栏输入 `shell:startup` 可直接打开这个文件夹。）

## 二、日常操作

**看它活着没：**

```powershell
curl.exe -s http://127.0.0.1:8000/healthz
netstat -ano | findstr ":8000.*LISTENING"
```

**看日志尾部：**

```powershell
Get-Content D:\ESP\evidence\backend_run.log -Tail 20
Get-Content D:\ESP\evidence\backend_guard.log -Tail 20
```

**停止（会同时停守护，否则守护会立刻把后端拉回来）：**

```powershell
D:\ESP\.venv\Scripts\python.exe D:\ESP\tools\stop_backend.py
```

**重新常驻启动：**

```powershell
D:\ESP\.venv\Scripts\python.exe D:\ESP\tools\run_backend_forever.py
```

或者双击 `tools\ESP_SensorBackend_Autostart.cmd`。

## 三、几点必须知道的

1. **守护进程是"用户级"的，只在登录后运行。** 它依赖启动文件夹，所以：注销/重启 → 登录后才起。
   如果要求"开机就有、不用登录"，那需要注册成 Windows 服务，**必须用管理员权限**（见第四节）。

2. **本方案不需要管理员权限。** 这也是选启动文件夹而不是系统服务的原因。

3. **`run_backend_forever.py` 不要用 `python.exe` 直接前台跑着不管** —— 虽然能用，
   但那个终端一关进程就没了。要常驻请用启动文件夹或 `pythonw.exe`（无窗口）。

4. **停止时务必用 `stop_backend.py`。** 直接 `Stop-Process` 杀掉后端没用 ——
   守护会在 3 秒内把它重新拉起来，看起来就像"杀不死"。

5. **重复启动是安全的。** 守护有单实例锁，第二个实例会自己退出；端口被占用时也不会硬抢。

## 四、（可选）做成真正的 Windows 服务

如果你希望**开机即运行、无需登录、且能在"服务"里管理**，需要管理员权限，
用现成脚本：

```powershell
# 以【管理员】身份打开 PowerShell
powershell -ExecutionPolicy Bypass -File D:\ESP\tools\install_service.ps1
```

或者手动：

```powershell
# 以【管理员】身份
New-Service -Name "ESP_SensorBackend" `
  -BinaryPathName '"D:\ESP\.venv\Scripts\python.exe" "D:\ESP\tools\run_backend_forever.py"' `
  -DisplayName "ESP 传感器后端" `
  -Description "接收 ESP32-S3 开发板上报的加速度数据并落库" `
  -StartupType Automatic
Start-Service ESP_SensorBackend
```

> 注意：`New-Service` 启动的程序**不会自动带上工作目录**，
> 而 `run_backend_forever.py` 内部全部用的是绝对路径，所以能正常工作。
> 但服务默认以 `LocalSystem` 运行，请确认它有权读写 `D:\ESP` 和数据库文件。

两种方式**不要同时用**（会起两个守护；虽然有单实例锁兜底，但没必要）。

## 五、排错：网页又打不开了怎么办

按顺序查：

1. `netstat -ano | findstr ":8000.*LISTENING"` —— 有没有在监听？没有就是后端没跑。
2. `Get-Content D:\ESP\evidence\backend_guard.log -Tail 20` —— 守护有没有在重拉？重拉报什么错？
3. `Get-Content D:\ESP\evidence\backend_run.log -Tail 40` —— 后端起不来的具体原因。
4. 看日志里开发板上报是 **201** 还是 **401**：
   - `401` → 令牌不匹配。对照 `firmware/src/app_config.h::APP_DEVICE_TOKEN`
     和 `backend/server.py::DEVICE_TOKEN`，两处必须一致。
   - `400 Bad request syntax` → HTTP keep-alive 错位（已在 server.py 修复，
     若复现请确认 `_send_json(..., close=True)` 那两处还在）。
5. 开发板是否在线：`ping 10.1.42.183`，以及板子 WiFi 有没有掉。

## 六、为什么不是"在 DSH 会话里挂着"

DSH 的后台任务会随会话结束而终止，**不适合做常驻**。所以这里用 Windows 自己的
启动机制（启动文件夹 / 系统服务），与 DSH 会话完全解耦。
