# 01 · 硬件接线与传感器说明

> 本文所有硬件参数（芯片型号、I2C 地址、寄存器值、引脚号）都不是抄来的猜测，
> 而是**在这块实体开发板上读出来并验证过的**。原始证据见 `evidence/` 目录。

---

## 1. 开发板与传感器

| 项目 | 实测结果 |
|---|---|
| 开发板 | **ESP32-S3-EYE**（ESP32-S3-WROOM-1-N8R8，8MB Flash + 8MB PSRAM） |
| 芯片 | ESP32-S3，双核，chip revision v0.2 |
| 板载传感器 | **QMA6100P 三轴加速度计**（上海矽睿 QST） |
| 传感器接口 | I2C，从机地址 **0x12**（7bit） |
| I2C 引脚 | **SDA = GPIO4，SCL = GPIO5** |
| CHIP_ID | 读寄存器 `0x00` → **0x90**（与数据手册一致） |
| 出厂固件自证 | 板子原来跑的官方示例日志里就打印了 `flip_dial: QMA6100P detected at 0x12` |

### 板载传感器 ≙ 无需额外接线

ESP32-S3-EYE 的 QMA6100P 是**焊在板上**的，通过板内 I2C 总线（GPIO4/GPIO5）连接，
因此**本方案不需要任何外部跳线**，上电即可采到真实的物理加速度值。

> 说明：ESP32-S3-EYE 的 BSP 头文件里 `BSP_CAPS_IMU` 标为 0（官方 BSP 没有封装 IMU API），
> 但芯片确实存在。本项目不依赖 BSP，直接按数据手册操作寄存器，因此不受该标记影响。

## 2. USB 接线（只用于烧录与调试）

ESP32-S3-EYE 板上有**两个 USB-C 口**，用途完全不同，别插错：

| 接口 | 丝印/位置 | 用途 | 说明 |
|---|---|---|---|
| **原生 USB 口** | 靠近板子一侧，直接连 ESP32-S3 的 GPIO19/GPIO20 | **本项目使用**：烧录 + 串口日志 | 电脑上会枚举成 `USB 串行设备 (COMx)`，本机实测为 **COM5**，芯片内部是 USB-Serial-JTAG |
| UART 口 | 另一个口，经 USB 转串口芯片 | 备用 | 若使用它，串口日志会跑到 UART0，需改 `sdkconfig.defaults` |

**本项目默认按「原生 USB 口」配置**（`CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG=y`），
所以请把数据线插在原生 USB 口上。

> ⚠️ 重要：USB 串口**只用于烧录和打印排错**。
> 正式的数据上传通道是板子自己连 Wi-Fi（STA 模式）后 POST 到后端，
> 与电脑是否插着 USB 完全无关 —— 这正是任务要求的架构。

### 怎么确认插对了口

Windows 上打开「设备管理器 → 端口(COM 和 LPT)」，
应能看到一个 `USB 串行设备 (COMx)`；或在 PowerShell 里执行：

```powershell
[System.IO.Ports.SerialPort]::GetPortNames()
```

## 3. QMA6100P 寄存器表（本项目实际使用的部分）

已通过实体芯片读回逐条验证。

| 地址 | 名称 | 属性 | 本项目用法 |
|---|---|---|---|
| `0x00` | CHIP_ID | 只读 | 校验 == `0x90`，确认芯片身份 |
| `0x01` | XOUTL | 只读 | X 轴低字节 |
| `0x02` | XOUTH | 只读 | X 轴高字节 |
| `0x03` / `0x04` | YOUTL / YOUTH | 只读 | Y 轴低/高字节 |
| `0x05` / `0x06` | ZOUTL / ZOUTH | 只读 | Z 轴低/高字节 |
| `0x0F` | RANGE | 读写 | 量程：`1`=±2g `2`=±4g `4`=±8g `8`=±16g `15`=±32g |
| `0x10` | BW_ODR | 读写 | 带宽/输出率：`0`=100Hz `1`=200 `2`=400 `3`=800 `4`=1600 `5`=50 `6`=25 `7`=12.5 |
| `0x11` | POWER_MANAGE | 读写 | bit7=1 进入测量模式；低 3 位主时钟分频（`0x04`=51.2kHz） |
| `0x36` | RESET | 写 | 写 `0xB6` 触发软复位 |

### 数据格式与单位换算（关键）

- 三轴数据寄存器是 **16bit，但内部只有 14 位有效数据且左对齐**，
  所以真实码值 = `(int16_t)((hi<<8) | lo) >> 2`（算术右移保留符号）。
- 满量程 = 14 位 → **8192**，因此 **灵敏度 = 8192 / 量程(g) LSB/g**：

| 量程 | 灵敏度 (LSB/g) | 分辨率 |
|---|---|---|
| ±2g（默认） | 4096 | 0.244 mg/LSB |
| ±4g | 2048 | 0.488 mg/LSB |
| ±8g | 1024 | 0.977 mg/LSB |
| ±16g | 512 | 1.95 mg/LSB |
| ±32g | 256 | 3.91 mg/LSB |

- 换算公式（固件与后端完全一致）：
  - `accel_g = raw / lsb_per_g`
  - `accel_ms2 = accel_g × 9.80665`
  - `magnitude_g = sqrt(gx² + gy² + gz²)`

### 为什么默认选 ±2g

板子通常静止或只做倾斜测量，±2g 的分辨率最高（0.244 mg/LSB），
静止时合矢量应稳定在 **1.000 g 左右**，这也是固件开机自检的判据。

## 4. 固件开机自检（判断传感器是否真的在工作）

固件启动后会做两件事，串口可以直接看到：

```
I (312) imu: 开始扫描 I2C 总线 ...
I (330) imu:   发现 I2C 设备: 0x12  <-- QMA6100P 加速度计
I (337) imu: 检测到 QMA6100P, I2C=0x12, CHIP_ID=0x90
I (352) imu: 配置回读: RANGE=0x01(±2g, 4096 LSB/g) BW_ODR=0x00 POWER=0x84
I (383) main: 硬件自检: 连续读取真实测量值, 检查合矢量是否接近 1g ...
I (800) main: 自检结果: 平均合矢量 = 1.00x g (20/20 次有效)
I (800) main: 自检通过: 读数符合静止状态下的真实重力加速度
```

如果 `CHIP_ID` 不是 `0x90`、或 I2C 扫描不到 `0x12`，固件会**明确报错并拒绝上报数据**
（绝不使用假数据顶替），此时请检查板子是否损坏或总线是否被占用。

## 5. 可选：外接传感器（换板子时用）

如果以后换用没有板载 IMU 的 ESP32-S3 开发板，按下面接线即可复用同一套固件：

| IMU 模块 | 模块引脚 | ESP32-S3 |
|---|---|---|
| QMA6100P / QMA7981 模块 | VCC(3V3) | 3V3 |
| | GND | GND |
| | SDA | GPIO4 |
| | SCL | GPIO5 |
| | SA0 | GND（决定地址为 0x12） |
| MPU6050 / MPU9250 | VCC/GND/SDA/SCL | 同上（地址 0x68/0x69，需改 `imu_qma6100p.c` 中的地址与寄存器表） |

注意：
- I2C 总线上必须有上拉电阻（多数模块自带 4.7kΩ）；本工程同时开启了芯片内部上拉。
- 走线尽量短，I2C 速率默认 400kHz，线长超过 30cm 时建议降到 100kHz。
