> 配套文档：接口字段级约定见 [`06_第2-3周接口文档_远程采集与按键反馈.md`](06_第2-3周接口文档_远程采集与按键反馈.md)；
> 测试用例见 [`08_第2-3周测试用例.md`](08_第2-3周测试用例.md)。
> 基线工程：第 1 周已跑通的 `firmware/` + `backend/server.py` + `web/`（见根 `README.md`）。
> **本周只开发应用层**：Wi-Fi 连接、SNTP 对时、HTTP(S)/TLS 客户端、反代与部署一律复用，不做底层通信改造。

## 0. 全局约束（每个任务都适用，写进 Definition of Done）

| 编号 | 约束 | 校验方式 |
|---|---|---|
| G1 | **无假数据**：测量值只能来自 `imu_qma6100p.c` 的寄存器读；读失败就报错跳过，不构造、不顶替、不补发 | 全仓 grep 无 `rand()`；拔掉传感器时串口只有 `ESP_LOGE`，数据库不新增行 |
| G2 | **旧值不可冒充新采集**：L1 身份（`request_id`+`nonce`）∧ L2 新旧性（`boot_count`/`seq`）∧ L3 时间性 三项同时成立才允许 `completed` | 重放第 1 周旧报文 → `409 STALE_OBSERVATION`，`status` 不变，`rejected_observations` 新增行（`TC-W2-*` 拒收组） |
| G3 | **超时 ≠ 硬件故障**：`timeout` 只由服务端 `deadline_utc` 计时产生；只有设备 `ack_type=rejected` 且 `reason=SENSOR_ERROR` 才算硬件问题 | 关机场景：`status=timeout` 且 `device_events` 中无 `sensor_error`；页面文案无"故障/损坏"字样 |
| G4 | **无远端回执不得声称已送达**：前端只能依据 `remote_acked_at_utc != null` 渲染"设备已收到回应" | DOM 断言（`TC-W3-*` 显示规则组） |
| G5 | **断网可用性**：按键识别与本地物理反馈（蜂鸣/LED/屏幕）不得依赖外网 | 关闭热点/拔网线后按键，串口 `[HELP]` 行与物理反馈仍发生 |
| G6 | **不接真实紧急电话**：仅教学接收端；无任何拨号/短信/报警联动代码 | 代码审查 + 交付说明中显式声明 |
| G7 | **第 1 周回归全绿**：`POST /api/v1/ingest`、`tools/verify_three_way.py`、`tools/selftest_backend.py`、`tools/analyze_db_rate.py`、`tools/test_web_stale.js` 均保持通过 | 每次合并前跑一遍，输出存 `evidence/` |
| G8 | **幂等与留痕**：重复点击、重复回执、重复观测都必须有确定结果，且**任何拒收都要留痕**（静默丢弃视为缺陷） | 幂等组用例 + `rejected_observations` 行数断言 |
| G9 | **模拟必须标注**：任何脚本伪造的回执/事件，文件名与页面标注 `SIMULATED`，不计入实物验收 | 交付物审查 |

**工时口径**：每个时段 = 2 学时。需求给定的理论/实践配比为
第 2 周前后段 `理论1+实践1` / `理论0+实践2`，第 3 周前后段 `理论1+实践1` / `理论0+实践2`。

## 6. 备用路径（当实物不可用 / 设备被占用时）

| 备用手段 | 能验证什么 | **不能**验证什么 | 标注要求 |
|---|---|---|---|
| 本地服务调试逻辑（后端跑本机、用 `tools/selftest_backend.py` 临时库） | 请求状态机、L1/L2/L3 拒收、超时扫描、幂等、取消规则、字段契约 | 真实板端采集、物理反馈、断网本地识别 | 证据文件加 `LOCALONLY` 前缀 |
| 共享设备轮换实测（按 §5 排班） | 真实板端链路与物理反馈 | 同时多人并发场景 | 文件名带使用者与时间戳 |
| 模拟回执（脚本伪造 `POST /device/ack`、`POST /observations`） | 后端状态机与页面渲染 | **不可作为实物验收**；不能证明板端真的采过 | 文件名与页面必须显示 `SIMULATED`，`docs/08` 中对应用例标"模拟" |
| 模拟按键（串口注入触发命令） | 上传/远端显示/回应/取消链路 | **实体输入输出**（按键与蜂鸣/LED 属必做项，不得用模拟替代） | 同上，且交付说明中写明"实体输入输出已另测" |

**硬性底线（需求原文）**：`实体输入输出必须完成` —— 即 **按键（实体输入）+ 至少一种实体反馈器件（实体输出）**
必须真实完成并留证据，模拟只能用于链路其余部分的补测。

## 8. Definition of Done（每个交付物的验收口径）

| 交付物 | DoD |
|---|---|
| **远程采集功能** | 网页点一次 → 后端 `status` 依次可见 `submitted`/`acked`（快路径）；设备串口出现新的 `[DATA]` 行；数据库 `observations` 有绑定行；`freshness ∈ {new_monotonic,new_after_reboot}` |
| **请求-回执-观测记录** | 用同一个 `request_id` 能联查 `collect_requests`/`request_acks`/`observations` 三表并互相印证（回执时刻 ≤ 观测时刻 ≤ 完成时刻） |
| **状态图** | 与实现逐边一致；含"拒收不改写状态"自环与终态集合；能用一个真实 `request_id` 的完整轨迹验证 |
| **动作执行追踪** | `GET /collect_requests` 能复盘连点两次的两条终局；含被拒次数 |
| **双向交互工程（按键+反馈）** | 实体按键 + 实体反馈均真实可用；断网时本地闭环仍成立；回应→设备确认→灯变 全链路可演示 |
| **任务说明** | 含硬件、接线、操作步骤、流程图、取消逻辑，第三人照文档能独立复现 |
| **走查改进记录** | 每条问题有现象/复现步骤/严重级/修复/复验状态；P0/P1 全关闭 |
| **迁移确认/取消机制** | 说明第 2 周与第 3 周"确认/取消"的同构关系；同一骨架复用，字段差异有表 |
