# 第 7 周：按需获取一张环境图像

> **这是第七周的任务交付。**
> 分支：`feature/week7-on-demand-snapshot`
> 技术细节见 [docs/15_第7周_按需获取一张环境图像.md](docs/15_第7周_按需获取一张环境图像.md)

---

## 一句话说明

用户点一下「看一次现场」，系统要么给他一张**请求之后真的拍到的**图，并说清这是**哪一刻**的画面；
要么明确告诉他这次**没拍到、为什么没拍到**。

**绝不给上一张。**

---

## 本周要回答的问题

> **"这张图是什么时候的？"——这句话如果答不实，图像就没有证据价值。**

所以本周做的不是"加一个拍照按钮"，而是把"一张图算不算本次采集"这件事，
拆成几条**可以被机器否决**的判据。

---

## 交付了什么

### 1. 一次请求 = 一条有终局的状态记录

```
pending → requested → capturing → ok / occluded
                              ↘ failed / timeout / cancelled
                              （终局之后到的图 → 另存 late，结论不改）
```

七个状态全部落库，前端同屏显示。**终局一旦命中，任何字段都不再被"更好的结果"改写。**

### 2. 三条红线，各自守在一行代码上

| 红线 | 判据 | 违反时 |
|---|---|---|
| 不把旧图当本次结果 | 帧序号必须**严格大于**基线 | `400 SNAPSHOT_STALE_IMAGE` |
| 终局不改写 | 超时/取消后到的图另存 `-late.jpg` | 终态字段一个都不动 |
| 失败不回退上一张 | 本次没有图像 | `409`，返回体里没有 JPEG 字节 |

> **为什么第二条要"收下但不认"**：图是证据，丢了就再也说不清"当时到底拍到了什么"；
> 但它不是**本次**的结论，所以只能进"迟到"字段，不能改 `state`。

### 3. 三个时刻分开存，精度也分开说

| 时刻 | 精确性 |
|---|---|
| 请求时刻 | 精确 |
| **快门时刻** | **估计**（设备没有与服务器对齐的时钟，UI 上一直标"（估计）"） |
| 到达后端 | 精确 |

快门时刻 = 到达 − 设备自报的「取帧→发请求」− 服务端量到的「收 body」。
两段都要减：只减前者会得到 0 毫秒的差，等于**把估计说成精确**（这个坑是第一版真机数据
`11513ms == 11513ms` 暴露出来的）。

### 4. 拍到没拍到，从字节里量，不靠猜

纯标准库解 baseline JPEG 的 **DC 系数**（跳过 IDCT），算平均亮度、块间标准差、暗块比例，
判定 `usable / occluded / unknown`。**15.6 毫秒/张，零第三方依赖。**

`occluded` 的图**照样存、照样能打开**——只是结论写"这次没看到环境"。
"不可用"和"没拍到"是两件事，不能混。

### 5. 三个口径绝不合并

| 来源 | 算不算"真的看到了" |
|---|---|
| 真机拍到 | ✅ |
| 协议模拟器（无硬件演练） | ❌ |
| 回放历史照片 | ❌ |

汇总接口分开返回 `live_ok / live_occluded / simulated / replayed`。
**合成一个"成功次数"，就再也回答不了本周那个问题。**

## 这周踩到的四个坑（都改了）

| 坑 | 现象 | 修法 |
|---|---|---|
| **冒号后的空格** | 后端日志写着"已下发"，板子却一次都没动作，固件不报错 | 解析器容忍 `"k":"v"` 与 `"k": "v"` 两种写法 |
| **Wi-Fi 省电** | 预览帧出现 11 秒断流，下发延迟 8~13 秒 | `esp_wifi_set_ps(WIFI_PS_NONE)`，改完降到 31~297 ms |
| **一次投递** | 那一帧的响应一丢，请求就凭空消失，前端只看到"超时" | 未确认期间每帧重发 + 设备按 id 去重 |
| **假精确** | 快门时刻 == 到达时刻 | 加上服务端量到的 `rx_ms`，并恒标"估计" |

> 共同点：**它们都不报错**。所以本周的验收判据全都落在"现场现象"和"库里字段"上，
> 不看"命令退出码"。

## 已知限制（如实说明）

1. **快门时刻是估计值**，误差上界是连接建立与首字节排队（几十毫秒）。
2. **occluded 只按亮度和平坦度判**：对着白墙、镜头盖、全黑房间都会判它。
   它保证的是"不把没信息的画面说成看到了环境"，不是"识别出遮挡物"。
3. **链路慢就是慢**：3KB 的 QVGA 图弱网下实测要 6.4 秒传完。
   所以超时窗口按实测分布定成 **35 秒**（原来 25 秒会把"链路慢"错判成"设备超时"，实测 2/10 假超时）。
4. **本轮截图里的画面是暗的**（平均亮度 16~24）。面板、时刻、判据都是真实数据；
   要一张好看的图，需要镜头前有光。
